# 下游差异比较与经验回流

先以当前源码证明差异及其影响，再把可复用的判断方法放回所属 Skill 或规范。回流用于改善 Harness 自身；下游的产品代码、身份、历史批准和技术路线继续由下游维护。本文解释 [积累与演进](project_lifecycle.md#14-harness-的积累与演进) 的实际阅读与写入路线，不新增自动审计或发布步骤。

## 固定比较对象

读取两个仓库当前的入口与策略，核对各自规范绝对路径、Git 顶层、HEAD、分支和已有改动。明确哪个是证据来源、哪个是实施目标；跨仓比较后继续实施时，不能因聊天仍绑定下游就把上游维护写回下游。

正向同步范围按 [升级范围与完成判定](../../.agents/skills/desktop-upgrade-harness/references/completeness.md) 使用已提交且干净的源 `inventory`。以同一份结果说明匹配、差异和缺失；运行时兼容与工程文件覆盖分别判断。回流写入后源工作树已经变化，不能再用旧提交冒充新知识的来源，也不能在脏源上登记下游已升级。

## 分类后决定是否回写

| 比较结果 | 处理 |
|---|---|
| 上游已经覆盖，目标也有实际接线 | 引用现有事实源；不重复添加规则或复制下游文案 |
| 产品专属差异 | 保留下游的脚本语言、目录、依赖来源、锁策略、身份和已批准能力；解释适配依据 |
| 可复用且有真实失败或源码证据的缺口 | 提炼触发条件、职责、验证和限制，回写精确所属入口 |
| 只有静态风险或历史说法 | 保留证据等级，必要时记入技术债；不把推测升级为新硬门禁 |

差异应能落到“哪个操作经过哪个模块、原来的不变量是什么、现有证据能证明什么”。例如，状态字段改为 getter 以后，调用方若仍持有可写锁和维护跨字段约束，封装问题仍未解决；文件与源一致也不代表版本相关资料适用于目标运行时。

## 按知识归属回写

| 知识 | 权威落点 | 入口与传播 |
|---|---|---|
| 通用文件、依赖和测试原则 | [工程规则](../ENGINEERING_RULES.md) | 根入口和相关 Skill 只路由；按既有实例化与升级合同核对 |
| 模块分层、状态所有权、任务能力和并发语义 | [重构参考](../../.agents/skills/desktop-refactor-code/references/state-and-dependency-boundaries.md) | 由重构与只读边界审查按需进入；随适用 Skill 传播 |
| 工程覆盖、运行时资料版本和实际命令接线 | [升级完成判定](../../.agents/skills/desktop-upgrade-harness/references/completeness.md) | 由升级入口进入；保留自有工程与完整受管流程的区别 |
| API、生成器、检查器或命令的真实行为变化 | 所属实现、模板及直接相关测试 | 核对源入口、新项目生成、裁剪和升级，不只修改 Skill 文案 |
| 回流方法及上游维护导航 | 本文与 [知识索引](../README.md) | 仅 Harness 源保留；不成为下游产品事实 |

通用参考使用中性示例，不硬编码某个产品的 crate 名、目录、账号、远端或发布结论。历史事实需要保留时，按 [文档事件与记录边界](../ENGINEERING_RULES.md#41-单一事实来源) 选择记录位置；源码与测试能解释的内容不再复制成第二套项目记忆。忽略的 `knowledge/` 是明确提取时生成的技术快照，不代替受管规则或 Skill 知识。

## 核对可达性与验证范围

新增参考从实际入口能到达，并保持所有链接在实例化、裁剪和升级后仍有效。所属 Skill 保留时参考也保留；仅上游方法论不得被复制到下游。复用现有文件选择与所有权机制，只有真实机制缺口才修改生成器或升级器。

纯文档回流检查修改文件的链接、锚点、规模与差异即可；涉及传播行为时选择直接相关的实例化、裁剪或 inventory 用例，涉及程序行为时补充对应行为回归。测试范围仍受 [测试范围门禁](../ENGINEERING_RULES.md#53-开发构建与完整验收) 约束，比较请求不自动授权全量测试、工具安装、产品迁移、构建、发布或推送。

完成回复区分本次只读比较结果、上游实际修改、已经运行的检查和待处理兼容缺口。保留两个仓库已有工作；按实际授权完成本地开发闭环，发布、推送和下游同步各自消费独立请求。
