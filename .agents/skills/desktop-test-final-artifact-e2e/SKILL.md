# 测试最终产物 E2E

通过真实用户或宿主使用的同一可见交互路径，验证已批准范围内的场景。

E2E 只在运行候选的实际系统取证。明确请求了跨平台构建时，交叉包仍须由对应系统承担运行场景，构建机不替目标系统验收。移动设备或模拟器的结果须注明实际运行系统和设备类型。

## 工作流程

1. 读取已批准成功标准、当前构建的 E2E 选择、`docs/VERIFICATION.md` 及适用接口 Skill。要求当前构建选择为 `enabled`，或存在已批准产品/渠道的 `required` 规则；`e2e_hint` 不能替代当前构建选择。
2. 从 [$desktop-verify-delivery 的候选范围](../desktop-verify-delivery/SKILL.md#候选范围) 接收已核对的完整真实最终产物、准入快照、已验证的 `acceptanceScope` 和按变化选出的场景。沿用同一候选集合、源码提交、构建身份和 manifest。NSH 使用从所选 `target`/`buildRun` 已解析出的实际制品路径。拒绝开发预览、源码调用、模拟后端、脚手架、占位内容或推测路径；没有 Work Plan 不阻断 E2E。
3. 按同一渠道上次发布到本次的变化确认场景，首发使用获批的初始交付范围。逐项覆盖实际改变的功能及受影响的既有交互，补上相关的失败路径；每项说明前置条件、隔离且可逆的数据、预期观测、清理和超时。仅执行这些场景及独立的必需检查。对不存在本目标可观察变化的项，说明原因和对应的构建/测试证据；全都无影响时把功能范围记为 `not-applicable`，照常执行制品核对和独立必需检查。
4. 启动真实产物，通过宿主提供的 Computer Use 工具与 GUI、浏览器、终端或宿主界面交互。按实际工具说明操作，每项动作前后复读状态。优先使用无障碍树，按最新截图定位坐标。宿主无法操作所需界面时，交回未执行场景及原因。
5. 验证状态、输出、持久化数据或错误呈现；单独一次点击或按键不构成证据。除非另获授权，必须在凭据、支付、生产、发布或不可逆操作前停止。
6. 在 runner 临时位置形成结构化的 `acceptanceScope`、产物/版本、源码提交、平台、每个场景对应的本次变化或独立硬要求、步骤、预期/观测结果、适用截图、关闭、清理和通过/失败结果，遮盖敏感信息与不必要个人路径；只把这些结果交回 `$desktop-verify-delivery` 作为待原子写入的候选证据，不直接逐个改写 release manifest，也不写 tracked Verification。
7. 任何失败、超时、取消或已启用但未运行的场景都拒绝候选并返回 `$desktop-implement-change` 增加回归测试；修复后重新构建完整候选。最终容器字节变化会使旧 E2E 证据失效；若变化同时影响运行时字节、启动器、配置、依赖或行为，必须重建并重跑。只有用户要求的活动计划存在时才重开或新增 Todo。
8. 所有场景和清理结束时，在准入选定的候选范围重新枚举精确文件集，并复算同一集合的最终制品、相邻摘要、manifest 声明及适用包内关键资源。NSH 按 [交付验收的候选范围](../desktop-verify-delivery/SKILL.md#候选范围) 重新解析并复核同一批次及其声明文件。要求源码提交、构建身份和每项字节与 E2E 准入快照一致。不得只声称“字节变化会使证据失效”而跳过结束复算；任何变化都使本次结果失效并交回 `$desktop-verify-delivery` 拒绝状态更新，不能把新摘要倒填进旧 manifest。
9. 未实际执行的操作系统、显示环境、浏览器、终端、MCP 宿主和包格式标记为 `Unverified`；必需人工最终复核仍是独立步骤，Agent 不得代签。

## 按变化选择接口场景

- CLI：真实二进制调用、输出流、退出状态、取消和关闭。
- MCP：批准真实宿主的发现、调用、错误、取消和干净断开。
- Tauri GUI：启动、完整用户闭环、无障碍状态、错误、持久化和干净退出。NSH 按 [NSH 场景](#nsh-场景) 选择实际目标环境。
- GUI 系统通知：当 `system_notification = enabled` 且当前候选运行在 macOS 时，先验证当前 `.app` 已按 manifest 的 enabled 路线完成签名；`disabled/not-requested` 或实际 unsigned 必须在读取权限前失败，不能以 E2E `disabled` 或 `Unverified` 绕过，也不能由本 Skill 补签。当通知行为在变化范围内或独立要求运行验证时，读取当前系统授权状态并选择不破坏用户决定的隔离场景。已授权时确认开关成功且持久化；明确拒绝/受限时点击开启必须打开固定 Notifications 系统设置、应用偏好保持关闭并显示稳定恢复信息；设置窗口无法打开时错误可见。`NotDetermined` 只有在用户明确允许本次权限提示时才触发请求并复读，否则记为 `Unverified`，不得为了测试重置或伪造系统授权。其他平台按其官方权限界面验证。
- GUI 更新日志（Tauri）：场景适用时，先从最终候选自身只读定位并校验 `release-notes.json`；`about_page = enabled` 时在真实应用打开关于页（`/about`），点击“更新日志”自身按钮，确认加载来自候选资源、按最新在前最多十版、每版固定“功能优化/问题修复”各最多十条、当前版本与全部版本仅一个小写 `v`，并验证关闭后重开仍显示同一候选事实。资源缺失/损坏的受控失败候选只在已有隔离夹具且无需破坏最终候选时验证本地错误与重试；不得改写正式候选制造失败。`about_page = disabled` 且关闭行为受影响时确认关于路由、入口、命令和弹窗均缺席。

## 完成输出

报告精确产物、同渠道基准版本和标签或首发、当前构建选择/硬要求来源、受影响变化及场景、可观察证据、清理、通过项、失败项和未验证范围。不得自行签署人工复核字段。

## NSH 场景

按验收传入的目标和批次运行已批准场景。目标支持的真实包格式见 `$desktop-build-nsh-release`。候选在实际桌面、移动宿主或 Web 浏览器执行；对未运行的目标、场景和格式记录 `Unverified`。

移动候选从实际安装的应用核对受影响的交互，例如安全区、底栏布局与选中态、切页、语言或主题。macOS 上先通过 Computer Use 检查可操作的 Device Hub（`com.apple.dt.Devices`，若可用）与 Simulator.app；`simctl` 可以辅助安装和截图，但未见 Simulator.app 窗口不足以判定模拟器无法点击。确无可操作界面时记录已检查的工具和未验证范围，不以 headless 渲染测试替代真实交互。

macOS NSH 官方 `.app` 归档从已解析的候选制品隔离解包，核对解包路径、Mach-O 入口、归档与 manifest SHA-256 后才启动。Web 只从候选归档的完整静态目录提供页面；Android APK 与 iOS 候选在适用的真实设备或模拟器上安装运行。Android AAB 使用宿主已有的 `bundletool`，从已校验摘要的候选原件在隔离目录生成设备适用的 APK 集，再安装到所选设备。证据记录 AAB 摘要、工具版本、设备和派生 APK 集摘要。该证据只覆盖本地设备运行。 [Android 官方 bundletool 指南](https://developer.android.com/tools/bundletool#deploy_apks_to_a_connected_device)

NSH 桌面关于页已启用且更新日志场景适用时，点击元素自身的“更新日志”按钮，逐语言对照候选清单绑定的 `release-notes.json` 两类与版本，观察编译进应用的内容。交互结束重新复算原始候选包、清单与 sidecar 字节，测试解包目录只在确认路径后清理。
