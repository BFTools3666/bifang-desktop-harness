# 升级范围与完成判定

用户要求“更新 Harness”“同步当前上游”时，范围是该源提交对当前接口适用的全部工程层。不得因同一请求还要求文件整理、修复或构建，就只同步那个子任务用到的规则。保留产品代码、依赖来源、身份、策略和本地决定，不表示可以省略与它们相容的工程要求。

## 先盘点，再构造候选

始终使用已核对的干净源提交中的 helper。下游已安装的旧升级器不能作为判断当前源覆盖是否完整的依据。先运行只读命令；它不要求目标已有所有权清单、策略或来源锁：

```text
node "<clean-harness-source-root>/.agents/skills/desktop-upgrade-harness/scripts/harness_upgrade.mjs" inventory --source-root "<clean-harness-source-root>" --source-version "<harness-version>" --source-commit "<harness-source-head>" --target-root "<downstream-root>"
```

`files` 来自源提交的已跟踪文件、源所有权规则和目标接口选择，覆盖通用 Skills、其 helper/测试/资产、混合规范、升级器自身和适用条件能力。上游专用文件、永久保护、初始化入口、退役能力与未选接口不进入清单。候选构造仍须按所有权策略渲染，不能直接复制原始源树。

NSH 的两套官方 Skills 还须从源 vendor 快照映射到实际安装路径 `.agents/skills/nsh/` 与 `.agents/skills/nsh-design-guides/`；清单中的 `source_path` 标明来源，不能只复制 vendor 而遗漏可调用的入口。

- `missing`：目标缺少工程文件，不能当作已同步。
- `review_required`：目标字节或权限不同，逐项确认身份渲染、本地定制或尚未同步的旧版本；它不表示允许覆盖。
- `matches_source`：文件与源一致，只证明文件传播，不证明项目命令已经接线。

`runtime.status: unsupported` 单独报告严格 NSH 合同的缺口，不阻止列出通用和所选接口的工程清单。它不放宽 `plan|apply|record` 的原有运行时门禁，也不授权改依赖、目录或产品运行器。盘点始终输出 `engineering_baseline: not_verified`，成功退出不是升级完成。

## 单独核对运行时知识的适用版本

`matches_source` 只说明与所选 Harness 源一致。原样安装的官方 Skill、设计指南和运行时参考也可能面向与目标不同的 NSH 版本；源固定版本低于目标版本同样属于当前合同不支持，不能把所有 `unsupported` 解释成目标版本过旧。

对照目标实际 Cargo 依赖、锁文件或解析结果、已有 CLI 版本证据和本地生成类型，说明哪些资料适用、哪些仍绑定源运行时。自有工程的 API 判断应使用与目标版本相符的生成类型和官方资料；这些证据只能说明目标现状，不能消除严格受管合同的拒绝。不改写 vendor 快照、不伪造来源锁，也不为使版本相等而降级或迁移产品。

## 核对实际接线

按盘点逐项标记“已同步”“已适配并验证”“不适用及依据”或“未完成及原因”。尤其核对本地开发、构建、发布、交付和验收入口是否消费新规则；仅修改版本说明、复制 Skill 或通过产品测试不能证明这些入口已升级。

对本地构建与交付至少核对现行命名和目录、源码与版本绑定、差异回归选择及结果、manifest/摘要和最终字节交付规则；根据当前接口判断适用项，不能把 NSH 自有运行器当作忽略通用交付规范的理由。这是升级范围核对，不触发构建、安装、E2E、产品发版或全量测试。只运行本次工程变化直接影响的相关测试或必要替代检查。

自有入口逐项记录“本地命令/模块 → 实际调用的上游模块 → 来源或适配差异 → 现有验证证据”。同时查看开发包和正式候选分支，确认正式路径确实消费发布上下文、精确回归结果和最终制品验证；模块被复制、导入或写进说明不代表该执行分支已经调用。产品专用脚本语言、目录与已批准策略不是通用知识缺陷，不能为匹配模板删除或改写它们。

`plan` 将完整源清单与快照写入 `source_inventory`。候选缺少仍适用的源路径时阻断，不能把遗漏解释成上游删除；升级器自身的可执行模块还须匹配源摘要。现有无需渲染的精确内容检查继续生效。新增源文件自动进入覆盖检查，不依赖维护一个必需路径白名单。`apply|record` 重算同一清单，不能以局部候选登记新版本。

## 报告真实结果

- **完整受管升级完成**：全部适用工程项已传播、混合规则和实际入口已核对，相关验证通过，来源锁成功记录，主流程规定的受保护状态后续检查也已完成。
- **部分同步完成**：只同步了精确列出的工程项，或自有 NSH 入口还不能进入严格受管流程；报告未同步项、兼容缺口与未建立的状态，不报告完整升级完成。
- **升级受阻**：列出实际 blocker 与已完成范围。不得自动切换依赖来源、产品框架、布局或锁策略来消除 blocker。
- **仅预览**：盘点或计划已生成，尚未应用、验证和记录基线。

自有 NSH 布局、registry 来源或 tracked 锁的兼容路径同样必须核对上述全集。不能只写“已同步上游版本”而不说明实际范围；用户未明确缩小范围时，不能自行把完整升级改成选择性同步。未能完成的项目在本次回复中保持可见，后续迁移只消费独立授权。
